## Rules

1. Inspect the existing frontend before changing anything.
2. Inspect the backend API routes and Postman documentation.
3. Do not invent API endpoints when an existing endpoint is available.
4. Do not use fake static data for completed features.
5. Add loading, empty, error, and success states everywhere.
6. Use strict TypeScript and avoid any.
7. Keep components small, reusable, and readable.
8. Do not duplicate API logic.
9. Do not expose backend secrets.
10. Preserve existing user changes.
11. Run lint and build after implementation.
12. Fix all TypeScript, ESLint, and build errors.
13. Use accessible HTML and keyboard navigation.
14. Make the interface responsive on mobile, tablet, and desktop.
15. Do not create only a marketing landing page. Build the actual application.

Implement registration, login, logout, refresh token handling, email verification, Google authentication, forgot password, reset password, protected routes, authenticated user state, unauthorized page, and session expiration handling.

Use a secure strategy compatible with the backend. Prefer HTTP-only cookies when supported. Never store private secrets in the browser.

## Implementation process

Work in phases and validate after each phase.

Phase 1: Foundation
- Install libraries
- Configure shadcn/ui, Tailwind tokens, dark mode, providers
- Add API client, types, global layout, sidebar, and navbar

Phase 2: Authentication
- Login, registration, logout, refresh, protected routes, password recovery, email verification

Phase 3: Dashboard
- Layout, statistics, projects, activity, tasks, notifications

Phase 4: Organizations and teams
- Switching, settings, invitations, teams, members

Phase 5: Projects and tasks
- CRUD, project details, task table, Kanban, task drawer, comments, attachments, labels

Phase 6: Sprints and activity
- Sprint CRUD, board, progress, activity timeline

Phase 7: Billing
- Plans, usage, upgrades, downgrades, cancellation, resume, invoices, payments, bKash flow

Phase 8: Quality
- Loading, empty, error states, mobile, accessibility, lint, TypeScript, production build

After each phase:
1. Explain changed files.
2. Run relevant validation.
3. Fix errors before continuing.
4. Do not silently skip unfinished features.
5. Inspect backend source when an API is ambiguous.

Start by inspecting the current frontend and backend. Implement Phase 1, then continue through all phases until the application is production-ready.
